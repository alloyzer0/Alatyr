# ADR-0001：以通用基础协议为仓库基线

- 状态：Proposed
- 日期：2026-10-01
- 范围：仓库组织和第一阶段架构边界

## 背景

框架可能被应用程序、游戏编辑器、物理模拟或资源工具使用。现在无法证明其中任何一个领域应该决定整个对象模型。如果一开始直接实现某个领域，Core 很容易被场景树、渲染、物理或编辑器需求污染。

## 决策

仓库采用“通用基线 + 领域验证”的结构：

1. `master` 只保存语言无关的基础协议、架构文档、测试场景和已经通过评估的通用实现；
2. 具体领域先以 `research/<domain>` 分支或 `examples/<domain>` 形式验证；
3. 领域实现必须通过适配器接入 Core，不直接修改 Core 的语义来满足局部需求；
4. 只有至少被两个独立领域复用，或明确属于稳定协议的内容，才考虑合并回 `master`；
5. 语言选型延后到协议和基准稳定之后；
6. 长期分歧的领域实现拆为独立模块或仓库，而不是维持永久分叉。

## 基线模块

```text
Core         身份、生命周期、所有权、引用、错误模型
Data         ComponentStore、PropertyStore、Query、Access
Schema       TypeRegistry、Schema、FieldDesc、约束、能力声明
Persistence  序列化、反序列化、迁移、资源解析、未知类型处理
Tools        Inspector、校验、Undo/Redo、资源浏览、热重载
Adapters     场景树、ECS、物理、渲染、网络、脚本、宿主集成
```

Core 不依赖具体领域。`ComponentStore` 只定义访问语义，具体布局可以由稀疏集合、连续数组、分页存储或 archetype 实现。

## 不变量

- 运行时句柄、持久化 ID 和 TypeId 分开建模；
- 类型 Schema 与实例值分离；
- 序列化不依赖内存地址或容器布局；
- 对象删除、悬空引用和未知类型都有确定结果；
- 未启用的能力不增加 Core 实例字段或每帧扫描；
- 编辑器、持久化和动态反射是可选模块；
- 领域特有语义不能通过隐式方式进入 Core。

## 尚未决定

本 ADR 不决定：

- 使用对象树、ECS 还是混合存储；
- 使用 Rust、Zig、C++ 或其他语言；
- 文本、二进制或混合持久化格式；
- 是否支持运行时新增类型、热重载和脚本；
- 并发、网络复制和插件 ABI 的最终模型。

这些问题通过领域原型、基准和后续 ADR 决定。

## 评估门槛

合并到 `master` 前，变化至少需要说明：

1. 它解决了哪个跨领域问题；
2. 它增加了哪些内存、编译或运行时成本；
3. 它如何处理旧数据、未知类型和失败回滚；
4. 至少一个正向案例和一个边界案例；
5. 如果没有合并，领域分支如何继续维护。
